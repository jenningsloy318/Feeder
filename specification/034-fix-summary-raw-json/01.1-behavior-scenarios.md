# Behavior Scenarios: Fix Summary Raw JSON Display

**Date:** 2026-03-17
**Author:** super-dev:bdd-scenario-writer
**Source:** ./034-debug-analysis.md
**Total Scenarios:** 14

## Acceptance Criteria Reference

- **AC-01**: Summary never shows raw JSON to user regardless of LLM response format
- **AC-02**: All existing summary functionality preserved (valid JSON, code blocks, plain text, legacy format)
- **AC-03**: Both OpenAI and Anthropic clients use shared parsing logic
- **AC-04**: Unit tests cover all identified edge cases

---

## Feature: Summary JSON Parsing and Display

### SCENARIO-001: Summary extracted from well-formed JSON response
**Acceptance Criteria:** AC-02 from requirements
**Priority:** P0

**Given** an article with AI summary enabled
**When** the AI provider returns a well-formed JSON response containing a summary field
**Then** the summary text is extracted and displayed to the user as readable content

### SCENARIO-002: Summary extracted from JSON inside a markdown code block
**Acceptance Criteria:** AC-02 from requirements
**Priority:** P0

**Given** an article with AI summary enabled
**When** the AI provider returns JSON wrapped in a markdown code block
**Then** the summary text is extracted from within the code block and displayed as readable content

### SCENARIO-003: Summary extracted when LLM wraps JSON in explanatory text
**Acceptance Criteria:** AC-01 from requirements
**Priority:** P0

**Given** an article with AI summary enabled
**When** the AI provider returns JSON embedded within conversational preamble or postamble text
**Then** the JSON object is located within the surrounding text, the summary is extracted, and displayed as readable content

### SCENARIO-004: Truncated JSON response handled gracefully
**Acceptance Criteria:** AC-01 from requirements
**Priority:** P0

**Given** an article whose content exceeds the AI provider's token limit
**When** the AI provider returns a response with incomplete or truncated JSON
**Then** the system displays a user-friendly error message instead of raw or partial JSON

### SCENARIO-005: Error message containing JSON is sanitized
**Acceptance Criteria:** AC-01 from requirements
**Priority:** P1

**Given** an AI provider experiencing a service issue
**When** the provider returns an error whose message contains embedded JSON
**Then** the system displays a sanitized error message without any raw JSON content

### SCENARIO-006: Double-encoded JSON string is handled gracefully
**Acceptance Criteria:** AC-01 from requirements
**Priority:** P1

**Given** an article with AI summary enabled
**When** the AI provider returns a double-encoded JSON string (JSON escaped within a string)
**Then** the system either extracts the summary from the decoded content or displays a user-friendly error message

### SCENARIO-007: Plain text summary displayed without modification
**Acceptance Criteria:** AC-02 from requirements
**Priority:** P0

**Given** an article with AI summary enabled
**When** the AI provider returns a plain text summary with no JSON structure
**Then** the plain text is displayed to the user as-is

### SCENARIO-008: Legacy format summary with language prefix is preserved
**Acceptance Criteria:** AC-02 from requirements
**Priority:** P1

**Given** an article with AI summary enabled
**When** the AI provider returns a response in the legacy "Lang: XX" format followed by summary text
**Then** the language is recognized and the summary text is displayed without the prefix

### SCENARIO-009: Empty summary field in valid JSON triggers error message
**Acceptance Criteria:** AC-01 from requirements
**Priority:** P1

**Given** an article with AI summary enabled
**When** the AI provider returns valid JSON but the summary field is empty or missing
**Then** the system displays a user-friendly error message instead of blank content

### SCENARIO-010: JSON with unrecognized structure is not displayed raw
**Acceptance Criteria:** AC-01 from requirements
**Priority:** P1

**Given** an article with AI summary enabled
**When** the AI provider returns valid JSON that does not contain the expected summary fields
**Then** the system displays a user-friendly error message instead of the raw JSON object

## Feature: Shared Parsing Logic

### SCENARIO-011: OpenAI-compatible client uses shared summary parser
**Acceptance Criteria:** AC-03 from requirements
**Priority:** P0

**Given** a user configured with an OpenAI-compatible AI provider
**When** a summary response is received from the provider
**Then** the response is processed through the shared summary parsing logic

### SCENARIO-012: Anthropic client uses shared summary parser
**Acceptance Criteria:** AC-03 from requirements
**Priority:** P0

**Given** a user configured with the Anthropic AI provider
**When** a summary response is received from the provider
**Then** the response is processed through the same shared summary parsing logic as all other providers

## Feature: UI Defense-in-Depth

### SCENARIO-013: UI layer catches any JSON that bypasses parsing
**Acceptance Criteria:** AC-01 from requirements
**Priority:** P0

**Given** a summary result that contains JSON content which was not caught by the parsing layer
**When** the summary is about to be displayed to the user
**Then** the UI detects the JSON content and substitutes a user-friendly error message

### SCENARIO-014: Truncated code block markup is not displayed raw
**Acceptance Criteria:** AC-01 from requirements
**Priority:** P1

**Given** a summary result that begins with code block markup but has no closing delimiter
**When** the summary is about to be displayed to the user
**Then** the system displays a user-friendly error message instead of raw markup
