# Spec 036: Persist Translation Cache -- Behavior Scenarios

## SCENARIO-001: Completed translation is saved to cache file

**Traces:** AC-001, NFR-001, NFR-002, NFR-003

**Given** an article with `itemId = 42` is open
**And** the target translation language is `zh` (Chinese)
**And** the article has 5 translatable paragraphs
**When** the user triggers `translate()` and all 5 paragraphs complete successfully (`translated == 1`)
**And** `TranslationState` transitions to `Translated`
**Then** the system persists the `ArticleTranslation` as gzip-compressed JSON
**And** the file is written to `filesDir/translations/42_zh.translation.json.gz`
**And** the file content, when decompressed, is valid `ArticleTranslation` JSON with all 5 paragraphs

---

## SCENARIO-002: Cached translation is loaded on article reopen

**Traces:** AC-002, AC-006

**Given** a cache file exists at `filesDir/translations/42_zh.translation.json.gz`
**And** it contains a fully completed `ArticleTranslation` (status `"translated"`)
**And** the current target language is `zh`
**When** the user opens article `itemId = 42` and triggers `translate()`
**Then** the system loads the cached `ArticleTranslation` from disk
**And** `TranslationState` transitions directly from `Empty` to `Translated`
**And** no LLM API call is made
**And** the translated paragraphs are rendered in the UI

---

## SCENARIO-003: No progress indicator shown for cached translation

**Traces:** AC-006

**Given** a valid cache file exists for article 42 in language `en`
**When** the user opens article 42 and triggers `translate()`
**Then** `TranslationState` never enters `Translating`
**And** no progress indicator (indeterminate or determinate) is displayed
**And** the translated content appears immediately

---

## SCENARIO-004: Language change does not serve stale cache

**Traces:** AC-003

**Given** a cache file exists at `filesDir/translations/42_en.translation.json.gz` (English translation)
**And** the user changes the target language setting to `zh` (Chinese)
**When** the user opens article 42 and triggers `translate()`
**Then** no cache hit occurs (file `42_zh.translation.json.gz` does not exist)
**And** the system performs a fresh LLM translation into Chinese
**And** on completion, a new cache file is written to `filesDir/translations/42_zh.translation.json.gz`
**And** the English cache file `42_en.translation.json.gz` remains untouched

---

## SCENARIO-005: Both language caches coexist independently

**Traces:** AC-003

**Given** cache files exist for article 42 in both `en` and `zh`
**When** the user opens article 42 with target language `zh` and triggers `translate()`
**Then** the Chinese cache is loaded
**And** the English cache is not affected
**When** the user later switches to `en` and triggers `translate()` again
**Then** the English cache is loaded

---

## SCENARIO-006: Partial translation failure is not cached

## SCENARIO-023: Translation cache survives app reinstall via backup

**Traces:** NFR-002

**Given** article `itemId = 42` has a cached translation at `filesDir/translations/42_zh.translation.json.gz`
**And** the app has `allowBackup="true"` in the manifest (default Android auto-backup)
**And** the `translations/` directory resides under `filesDir` (which is included in Android auto-backup by default)
**When** the user uninstalls the app
**And** the user reinstalls the app on the same device with the same Google account
**And** Android auto-backup restores the `filesDir` contents
**Then** the file `filesDir/translations/42_zh.translation.json.gz` is present after restore
**And** when the user opens article 42 with target language `zh` and triggers `translate()`
**Then** the cached translation is loaded from the restored file
**And** no LLM API call is made

> **Implementation note:** The `filesDir` location is backup-eligible by default under Android's auto-backup when `allowBackup="true"`. This is the same mechanism that preserves the Room database file and article blob files across reinstalls. The `cacheDir` is explicitly excluded from backup by Android, which is why translation cache must NOT use `cacheDir`. If custom backup rules (`fullBackupContent` or `dataExtractionRules`) are added in the future, the `translations/` directory must be explicitly included.

---

## SCENARIO-024: Translation cache is available after app update

**Traces:** NFR-002

**Given** the user is running app version N
**And** article `itemId = 42` has a cached translation at `filesDir/translations/42_zh.translation.json.gz`
**When** the user updates the app to version N+1 (standard Google Play or F-Droid update)
**Then** the `filesDir/translations/` directory and all its contents are preserved (app updates do not clear `filesDir`)
**And** the file `42_zh.translation.json.gz` still exists and is readable
**When** the user opens article 42 with target language `zh` and triggers `translate()`
**Then** the cached translation is loaded successfully
**And** no LLM API call is made

> **Implementation note:** Android app updates preserve the entire app data directory (`filesDir`, `cacheDir`, databases). This scenario validates that the serialization format remains backward-compatible across versions -- the `ArticleTranslation` `@Serializable` class must not introduce breaking schema changes without a migration path.
